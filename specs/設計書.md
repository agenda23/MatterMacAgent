## 1. システムアーキテクチャ

### 1.1 全体構成

3つのプロセスが Tauri アプリケーションとして統合される。

```
[Google Home / Apple Home / Alexa]
         ↕ Matter over Wi-Fi (UDP/TCP/IPv6 - LAN内)
[スマートホームハブ (Nest Hub / HomePod / Echo)]
         ↕
┌─────────────────────────────────────────────────────┐
│ Matter Mac Agent (.app)                              │
│                                                      │
│  [React Webview]                                     │
│       ↕ Tauri IPC（ポート開放なし）                   │
│  [Rust Core (Tauri)]                                 │
│   ・アプリライフサイクル / メニューバー常駐             │
│   ・Sidecar プロセス管理                              │
│   ・config.json 読み書き                              │
│   ・macOS 権限チェック                                │
│       ↕ stdin/stdout JSON メッセージング              │
│  [Node.js Sidecar]                                   │
│   ・Matter Bridge ノードのホスティング（matter.js）    │
│   ・ON/OFF イベント受信 → アクション実行              │
│   ・QRコード情報の生成・送出                           │
└─────────────────────────────────────────────────────┘
```

### 1.2 コンポーネント別責務

| コンポーネント | 技術 | 責務 |
|---|---|---|
| フロントエンド | React + TypeScript | 設定 UI・QRコード表示・権限ステータス表示 |
| バックエンド | Rust + Tauri 2.x | アプリ全体の統括・Sidecar 管理・IPC・ファイル I/O・OS 権限 |
| サイドカー | Node.js + matter.js | Matter プロトコル処理・アクション実行 |

### 1.3 プロセス間データフロー

```
設定変更フロー:
  React (ユーザー操作)
    → Tauri IPC [save_config]
    → Rust (config.json 書き込み)
    → stdin [config_update]
    → Node.js Sidecar (マクロ割り当てをメモリに反映)

ON/OFF 実行フロー:
  スマートホームハブ
    → matter.js (onOff$Changed イベント)
    → アクション実行 (child_process)
    → stdout [action_result]
    → Rust (結果を中継)
    → Tauri イベント [action-error]
    → React (エラートースト表示)

ペアリング情報フロー:
  matter.js 起動時 (QRコード生成)
    → stdout [qr_code]
    → Rust (メモリに保持)
    → Tauri IPC [get_pairing_info]
    → React (QRコード画像・PIN を表示)
```

## 2. フロントエンド設計（React）

### 2.1 コンポーネント構成

```
App
├── TrayPopover          # メニューバーアイコンクリック時のポップオーバー
└── DashboardWindow      # メインウィンドウ
    ├── HomeTab          # ステータス・QRコード・権限
    ├── SwitchTab        # 10スイッチ一覧・マクロ割り当て
    ├── MacroTab         # マクロ一覧
    │   └── MacroEditor  # マクロ作成・編集モーダル
    │       └── ActionEditor  # アクション1件の入力フォーム
    └── SettingsTab      # 自動起動・開発者モード
```

### 2.2 状態管理

- グローバル状態: `Config` オブジェクト（React Context または Zustand）
- 初期化: アプリ起動時に `invoke("get_config")` で取得
- 更新: 変更のたびに `invoke("save_config", { config })` でアトミックに保存

### 2.3 QRコード生成

`qrcode` ライブラリ（または `qrcode.react`）を使用し、Rust から受け取った `qr_payload` 文字列から QRコード画像をクライアントサイドでレンダリングする。Rust 側は文字列のみ保持し、画像生成は React の責務とする。

## 3. バックエンド設計（Rust / Tauri）

### 3.1 Tauri コマンド実装方針

```rust
#[tauri::command]
async fn get_config(state: tauri::State<'_, AppState>) -> Result<Config, String> { ... }

#[tauri::command]
async fn save_config(config: Config, state: tauri::State<'_, AppState>) -> Result<(), String> {
    // 1. config.json に書き込み
    // 2. Sidecar に config_update を送信
}
```

### 3.2 Sidecar プロセス管理

```rust
// アプリ起動時
let sidecar = app.shell().sidecar("matter-sidecar")?;
let (mut rx, child) = sidecar.spawn()?;

// stdout の非同期読み取り
tokio::spawn(async move {
    while let Some(event) = rx.recv().await {
        match event {
            CommandEvent::Stdout(line) => dispatch_sidecar_message(&app_handle, &line),
            CommandEvent::Terminated(_) => emit_sidecar_offline(&app_handle),
            _ => {}
        }
    }
});

// アプリ終了時: child.kill() で Sidecar を確実に終了
```

### 3.3 stdin への書き込み

```rust
fn send_to_sidecar(child: &mut CommandChild, msg: &SidecarMessage) -> Result<()> {
    let json = serde_json::to_string(msg)? + "\n";
    child.write(json.as_bytes())?;
    Ok(())
}
```

### 3.4 macOS 権限チェック

`accessibility-sys` クレートを使用して `AXIsProcessTrusted()` を呼び出す。

```rust
#[tauri::command]
fn get_permissions() -> PermissionStatus {
    PermissionStatus {
        accessibility: check_accessibility(),
    }
}

#[cfg(target_os = "macos")]
fn check_accessibility() -> bool {
    unsafe { accessibility_sys::AXIsProcessTrusted() }
}
```

### 3.5 設定ファイルの読み書き

Tauri の `app.path().app_data_dir()` で取得したディレクトリに `config.json` を配置する。ファイルが存在しない場合（初回起動）は初期値の JSON を生成して保存する。

## 4. サイドカー設計（Node.js + matter.js）

### 4.1 Matter Bridge 実装

matter.js の `ServerNode` + `AggregatorEndpoint` + `OnOffPluginUnitDevice` を組み合わせて Bridge を構成する。

```typescript
import { ServerNode, Endpoint } from "@matter/main";
import { AggregatorEndpoint } from "@matter/main/endpoints";
import { OnOffPluginUnitDevice } from "@matter/main/devices";
import { BridgedDeviceBasicInformationServer } from "@matter/main/behaviors";

const server = await ServerNode.create({ id: "matter-mac-agent" });

const aggregator = new Endpoint(AggregatorEndpoint, { id: "aggregator" });
await server.add(aggregator);

// 10個の子デバイスを固定追加 (Endpoint ID 2〜11)
for (let i = 1; i <= 10; i++) {
  const device = new Endpoint(
    OnOffPluginUnitDevice.with(BridgedDeviceBasicInformationServer),
    {
      id: `switch-${i}`,
      bridgedDeviceBasicInformation: {
        nodeLabel: config.endpoints[i - 1]?.name ?? `仮想スイッチ ${i}`,
        reachable: true,
      },
    }
  );
  device.events.onOff.onOff$Changed.on((value: boolean) => {
    handleSwitchEvent(i, value);
  });
  await aggregator.add(device);
}

await server.start();

// QRコード情報を Rust へ送信
const { qrPairingCode, manualPairingCode } = server.state.commissioning.pairingCodes;
sendToRust("qr_code", { qr_payload: qrPairingCode, manual_code: manualPairingCode });
sendToRust("ready");
```

### 4.2 アクション実行エンジン

```typescript
async function handleSwitchEvent(switchIndex: number, isOn: boolean): Promise<void> {
  const endpoint = config.endpoints.find(e => e.id === switchIndex);
  if (!endpoint?.assigned_macro_id) return;

  const macro = config.macros.find(m => m.id === endpoint.assigned_macro_id);
  if (!macro) return;

  const actions = isOn ? macro.on_actions : macro.off_actions;
  for (let i = 0; i < actions.length; i++) {
    try {
      executeAction(actions[i], config.system.developer_mode);
      sendToRust("action_result", { endpoint_id: switchIndex + 1, action_index: i, success: true });
    } catch (err) {
      sendToRust("action_result", { endpoint_id: switchIndex + 1, action_index: i, success: false, error: String(err) });
      // フェイルオープン: 後続アクションを継続
    }
  }
}
```

### 4.3 stdin メッセージ受信

```typescript
let buffer = "";
process.stdin.on("data", (chunk: Buffer) => {
  buffer += chunk.toString();
  const lines = buffer.split("\n");
  buffer = lines.pop() ?? "";
  for (const line of lines) {
    if (!line.trim()) continue;
    const msg = JSON.parse(line);
    switch (msg.type) {
      case "config_update": config = msg.payload; break;
      case "shutdown": server.close().then(() => process.exit(0)); break;
    }
  }
});
```

## 5. Sidecar バイナリ化設計

### 5.1 ツール選定方針

`pkg`（Node.js 18 以降で非推奨）の代替として以下を Phase 1 で検証する。

| ツール | 長所 | 注意点 |
|---|---|---|
| `@yao-pkg/pkg` | `pkg` の公式後継。Node.js 20 対応。既存 Node.js エコシステムと互換性が高い | `matter.js` の動的 `require` / native addon の snapshot 動作を要検証 |
| `bun build --compile` | ESM ネイティブ対応。ビルドが高速 | `dgram`, `net` 等の Node.js コア API の互換性要確認 |

### 5.2 Universal Binary 対応

```json
// tauri.conf.json
{
  "bundle": {
    "externalBin": ["binaries/matter-sidecar"]
  }
}
```

Tauri は自動的にターゲットアーキテクチャに対応するバイナリ（`matter-sidecar-aarch64-apple-darwin`, `matter-sidecar-x86_64-apple-darwin`）を選択してバンドルする。
