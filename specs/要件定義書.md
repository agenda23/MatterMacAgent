**バージョン**: 1.0
**作成日**: 2026-06-12
**関連文書**: [仕様書](仕様書.md) / [設計書](設計書.md)

## 1. プロジェクト概要

### 1.1 背景

音声アシスタント（Siri, Google Assistant, Alexa）からMacを操作する既存手段はすべてクラウドを経由する。IFTTTや各アシスタント固有のスキル開発では、1〜3秒程度の遅延・プラットフォームごとの実装差異・API制限という問題を抱える。

本プロジェクトでは、業界統一のローカルスマートホームプロトコルである **Matter** を活用し、MacをスマートホームデバイスとしてLAN内に直接統合する。クラウドを一切経由しないため、応答遅延はLAN内通信速度（数十ms以下）に収まる。

### 1.2 目的

- Mac を Matter Bridge デバイスとしてスマートホームに統合し、音声・スマートホームアプリから直接macOSを操作できる環境を提供する
- 技術知識のない一般ユーザーでも QRコード1枚のスキャンでセットアップが完了する配布形式（.dmg）で提供する

### 1.3 プロジェクト名・識別子

- アプリ名: **Matter Mac Agent**
- Bundle ID: `com.matter-mac-agent`

## 2. スコープ定義

### 2.1 スコープ内

- macOS 向けメニューバー常駐アプリの開発
- Matter Bridge として Google Home / Apple Home / Amazon Alexa からの ON/OFF 制御を受け付けること
- 10個の仮想スイッチ（静的エンドポイント）の提供
- 各スイッチへのマクロ（アクション群）割り当て
- macOS ショートカット / URL開く / シェルコマンド / AppleScript の実行
- `.dmg` インストーラーによる配布

### 2.2 スコープ外

| 項目 | 理由 |
|---|---|
| Windows / Linux 対応 | macOS 固有の自動化機能（ショートカット, AppleScript）への依存 |
| クラウドサービスへのデータ送信 | ローカル完結がコアバリュー |
| Matter 以外のプロトコル（Zigbee, Z-Wave 等） | スコープ過大 |
| リモート（LAN 外）からの制御 | セキュリティ設計の複雑化 |
| スマートホームハブ機能 | 本アプリはデバイス側であり、コントローラーではない |
| 音声認識機能 | 音声認識はスマートホームハブ側の役割 |
| Dimmer / 音量調整などの連続値制御 | 初期バージョンでは ON/OFF（OnOffPluginUnit）に限定 |

## 3. ユーザー定義

### 3.1 一般ユーザー

- スマートホームデバイス（Google Home / Apple Home）を日常的に利用している
- 音声またはスマホアプリからMacを操作したい
- シェルコマンドの知識は不要
- macOS「ショートカット」アプリで自動化を作成できる（または学習コストなしに使いたい）

### 3.2 開発者ユーザー

- ターミナル操作・シェルスクリプトに慣れている
- Docker, IDE, ローカルサーバーなどの開発環境をワンアクションで制御したい
- AppleScript による細かい UI 操作も行いたい

## 4. ユースケース

| ID | タイトル | ユーザー | シナリオ |
|---|---|---|---|
| UC-01 | 開発環境の一括起動 | 開発者 | 「Hey Siri, 開発モードをオンにして」で VS Code 起動・Docker 起動・ブラウザ指定 URL を開く |
| UC-02 | 映画タイムの設定 | 一般 | スマートホームのシーンボタンで画面輝度を下げ、通知をミュートし、Netflix を開く（macOS ショートカット経由） |
| UC-03 | 即時スリープ | 一般 | 「Macを消して」で画面ロック＋スリープを即座に実行 |
| UC-04 | ブラウザリロード | 開発者 | 物理スマートボタンを押してアクティブなブラウザに Cmd+R を送信（macOS ショートカット経由） |
| UC-05 | 初回ペアリング | 一般 | QRコードを1枚スキャンするだけで、10個のスイッチがスマートホームアプリに自動登録される |
| UC-06 | マクロの変更 | 一般 | スマートホーム側の再ペアリングなしに、スイッチに割り当てるアクションを変更する |

## 5. 機能要件

### 5.1 Matter デバイス機能

| ID | 要件 |
|---|---|
| FR-001 | Matter Bridge（Aggregator デバイスタイプ）として動作し、QRコード1枚でコミッショニングできること |
| FR-002 | コミッショニング後、スマートホームアプリ上に10個の仮想スイッチが**独立したデバイス**として自動登録されること |
| FR-003 | 各仮想スイッチは ON/OFF の2状態を持ち、スマートホームアプリおよび音声アシスタントから制御できること |
| FR-004 | スマートホーム側の再ペアリングを発生させずにマクロの割り当てを変更できること |
| FR-005 | ペアリング用 QRコード と Manual Pairing Code（数字コード）をダッシュボードに表示できること |

### 5.2 アクション実行機能

| ID | 要件 |
|---|---|
| FR-006 | macOS「ショートカット」アプリのショートカット名を指定してアクションを実行できること |
| FR-007 | URL またはアプリ名を指定して開くアクションを実行できること |
| FR-008 | シェルコマンドを実行できること（開発者モードが有効な場合のみ） |
| FR-009 | AppleScript を実行できること（開発者モードが有効な場合のみ） |
| FR-010 | 1つのスイッチの ON 時・OFF 時それぞれに複数アクションを順次実行するマクロを設定できること |

### 5.3 UI・設定機能

| ID | 要件 |
|---|---|
| FR-011 | macOS のメニューバーにアイコンを常駐表示し、クリックでダッシュボードを開けること |
| FR-012 | 各仮想スイッチに名前をつけ、マクロを割り当てる UI を提供すること |
| FR-013 | マクロを作成・編集・削除できるエディタ UI を提供すること |
| FR-014 | 「ログイン時に自動起動」を UI 上のトグルで設定できること |
| FR-015 | 「開発者モード」を UI 上のトグルで有効化できること。デフォルトは無効 |
| FR-016 | アクセシビリティ / オートメーション権限の付与状態を表示し、未付与の場合はシステム設定の該当箇所へワンクリックで誘導できること |

## 6. 非機能要件

| ID | 要件 | 補足 |
|---|---|---|
| NFR-001 | 完全ローカル動作 | 外部サーバーへの通信を一切行わないこと |
| NFR-002 | ポート非公開 | localhost のポートを開放しないこと。UI とコア間は Tauri IPC 通信のみ |
| NFR-003 | 軽量動作 | アイドル時のメモリ使用量を最小化すること（Electron 比で顕著に軽量であること） |
| NFR-004 | 配布形式 | `.dmg` インストーラーとして提供し、一般ユーザーがダブルクリックでインストールできること |
| NFR-005 | プラットフォーム | Apple Silicon (ARM64) および Intel (x86_64) の両 Mac に対応すること |
| NFR-006 | OS 要件 | macOS Ventura (13.0) 以降を対象とする |
| NFR-007 | プライバシー | ユーザーの操作ログ・設定情報を LAN 外へ送信しないこと |

## 7. 制約条件

| 制約 | 内容 |
|---|---|
| Matter ペアリング制約 | Bridge の Endpoint 構成（数・順序）を変更するとスマートホーム側で再ペアリングが発生する。このため仮想スイッチ数は **10個固定** とし、アプリバージョンをまたいでも変更しない |
| macOS 権限要件 | アクセシビリティ権限・オートメーション権限をユーザーが手動で付与する必要がある。アプリはこれをガイドするが、自動付与はできない |
| `nut-js` 不採用 | Apple Silicon での動作不安定を理由に、キーシミュレートライブラリ `nut-js` は採用しない。キーシミュレートが必要なユースケースは macOS ショートカットアプリで代替する |
| バイナリ化ツール | Node.js 18 以降で `pkg` が非推奨のため、`@yao-pkg/pkg` または `bun build --compile` を採用する（Phase 1 で互換性を検証） |

## 8. 受け入れ基準

| ID | 基準 |
|---|---|
| AC-001 | Google Home アプリの QRコードスキャンで10個のスイッチが独立したデバイスとして登録される |
| AC-002 | Apple Home アプリの QRコードスキャンで10個のスイッチが独立したデバイスとして登録される |
| AC-003 | 「Hey Siri, [スイッチ名]をオんにして」でスイッチの ON トリガーが発火し、割り当てたマクロが実行される |
| AC-004 | マクロ変更後、スマートホーム側で再ペアリングなしに新しいアクションが実行される |
| AC-005 | 開発者モードが OFF の状態でシェルコマンド・AppleScript の登録 UI が表示されない |
| AC-006 | 開発者モードが OFF の状態で `shell` / `applescript` タイプのアクションを Sidecar 側でも実行拒否する |
| AC-007 | アクセシビリティ権限が未付与の状態でアプリを起動すると、権限不足の警告とシステム設定への誘導リンクが表示される |
| AC-008 | Mac 再起動後、自動起動設定が有効な場合はログイン時に自動でアプリが起動し、スマートホームからの制御が再開される |
