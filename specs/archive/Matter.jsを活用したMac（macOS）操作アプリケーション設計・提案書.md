本資料は、ローカル通信規格「Matter」のオープンソース実装である `matter.js` を活用し、Macを仮想的なスマートデバイスとしてスマートホームシステム（Google Home, Apple Home, Amazon Alexa 等）にネイティブ統合し、ローカル低遅延で複数操作・汎用マクロを実行するためのアプリケーション設計書です。

## 1. プロジェクトの背景と基本コンセプト

従来のスマートスピーカーからPCを操作するアプローチ（IFTTTなどのクラウド経由、または各アシスタント固有のカスタムスキル開発）は、「遅延が大きい」「プラットフォームごとに実装が異なる」「セットアップが複雑」という課題を抱えていました。

本プロジェクトでは、業界共通のローカルスマートホーム規格 **「Matter」** を採用します。

## 2. 技術スタックの選定

- **フロントエンド (UI):** React（Tauri経由で実行）
- **デスクトップラッパー (GUIエンジン):** **Tauri**
- **バックエンド・OS制御 (サイドカー):** **Node.js + matter.js**
    - **macOS制御ライブラリ:** `child_process` (シェル実行用)
    - **⚠️ 注意**: `nut-js` は Apple Silicon (M1/M2/M3) での動作が不安定。Tauri ネイティブ版ではキーシミュレートを廃止し、**macOS ショートカットアプリによる代替**を推奨方針としている。

## 3. 静的エンドポイントマッピング

1. **固定の空エンドポイントを定義:** アプリ起動時に、あらかじめ「仮想スイッチ1」〜「仮想スイッチ10」のように、固定で10個の `OnOffPluginUnitDevice` をMatterサーバーに登録して起動します。
2. **スマートホーム側では1回だけ登録:** ユーザーは初回セットアップ時に、この10個のスイッチ群を1度だけ一括でGoogle Home / Apple Home等に登録します。
3. **GUI側で動的に機能割当て:** スマートホーム側の再登録を一切必要とせずにマクロの追加・変更が可能となります。

## 4. マクロ登録機能 (データ構造・旧版)

```json
[
  {
    "id": "macro_developer_mode",
    "name": "開発モード",
    "assigned_endpoint": 1,
    "on_actions": [
      { "type": "command", "value": "open -a 'Visual Studio Code'" }
    ],
    "off_actions": []
  },
  {
    "id": "macro_browser_reload",
    "name": "ブラウザリロード",
    "assigned_endpoint": 2,
    "on_actions": [
      { "type": "keystroke", "keys": ["command", "r"] }
    ],
    "off_actions": []
  }
]
```
